# 资源隔离与最小证据原则

日期：2026-11-16（Asia/Shanghai）
材料性质：Astra/high 只读架构审核、项目规则落盘决策
关联批次：规则维护批次；无运行时 `runId`

## 结论

独立运行目录只应隔离会互相影响的可变状态，不应默认复制整个 Electron、依赖树或官方运行时。来源、版本、哈希、权限、架构、路径和链接语义均已确认稳定且只读的输入应优先复用。复制或重定位前，必须先证明共享会产生干扰，或存在安全、合规或并发理由。

本原则采用两层落盘：跨项目的抽象规则写入 `D:\project\codex\AGENTS.md`；DSH 的运行目录、`user-data`、`DSH_HOME`、官方归档和启动验收等具体适配写入本项目 `AGENTS.md`。历史案例、命令、日志、哈希和失败回执仍保留在 `docs/` 与 `.runs/`，不写入全局规则正文。

## 审核依据

- 文件事实：全局规则已有“目标对齐、证据驱动和反馈修正”，项目规则已有 run 隔离、pre-snapshot、启动门禁和错误分诊。
- 历史实验事实：复制大规模依赖树曾破坏 pnpm 链接并导致 `js-yaml` 无法解析；已校验的 Electron 复用后窗口可以出现，失败点在 Host 依赖。
- 架构建议：全局定义四类对象、共享与隔离的判据、最小充分证据和长任务终止条件；项目只定义 DSH 的状态和验收落点。

## 稳定规则

先区分可变状态、不可变输入、产出物和证据。干扰是一个操作能够改变、锁定、遮蔽或重新解释另一个操作观察到的输入或状态，并足以改变结果、可重复性、安全性或结论。稳定不可变资源必须在任务期间预期不被写入，并且其来源、版本、哈希、权限、架构、路径和链接语义均符合目标。

最小充分证据必须能够验证当前阶段的必要条件、区分候选方案并作出继续或停止判断；负证据（失败输出、进程残留、权限拒绝、链接断裂）与通过证据同等重要。强制审计和回滚义务所需的原始材料必须保留，其他不能改变判断的读取、复制和运行不执行。

长耗时操作开始前必须记录必要条件、成功判据、停止条件和回滚点，并先执行最快、最小、可逆的验证动作。出现新根因、范围、版本、哈希、路径或进程偏差时，停止当前 run，保留原始回执并使用新的 run 分诊。
